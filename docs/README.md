# Documentation Index

Use `docs/` for information that explains the system or decisions across multiple days or projects. Keep day-specific instructions close to the code in each day folder.

## Folders

- `architecture/` — current system diagrams, components, data flow, trust boundaries.
- `adr/` — Architecture Decision Records: context, options, decision, consequences.
- `interview-notes/` — concise explanations and questions you can answer aloud.
- `system-design/` — design exercises, requirements, estimates, bottlenecks, trade-offs.
- `retrospectives/` — weekly reviews and lessons learned.

## Naming

Use lowercase kebab-case and descriptive names, for example:
- `architecture/order-processing-context.md`
- `adr/0001-use-postgresql-for-primary-data.md`
- `system-design/url-shortener.md`
- `retrospectives/week-01.md`

Do not duplicate the entire README of a project here. Link to the canonical project documentation.
